# Creative Automation Pipeline — Campaign AI

A proof-of-concept **creative automation pipeline** for scalable social ad
campaigns. It turns a **campaign brief** (plus a person, a product, and an
optional logo) into finished social-ad creatives — a photorealistic hero image
generated by Google's Gemini **"Nano Banana"** model, rendered into **three
aspect ratios** (1:1, 9:16, 16:9), with the **campaign message** overlaid and
automated **brand + legal compliance checks**.

It ships with two interfaces: a **command-line pipeline** and a local
**"Campaign AI" web studio** that streams every stage live in the browser.

Built for the FDE take-home: *Creative Automation for Scalable Social Ad Campaigns.*

## 1. What it does

For a campaign, the pipeline:

1. **Resolves a hero image per product.** It reuses an existing input asset if
   one is present for that product; otherwise it **generates** one with Gemini
   "Nano Banana", conditioned on any reference images provided (person, product,
   logo).
2. **Produces creatives** for **1:1 (1080×1080)**, **9:16 (1080×1920)**, and
   **16:9 (1920×1080)**. For a *generated* hero it renders each ratio
   **natively** with Nano Banana — the 1:1 is the master, and 9:16/16:9 are
   re-composed from it (passed back as a reference) so the person, product, and
   logo are never cropped; the model extends the scene instead. Reused/uploaded
   heroes use a subject-aware center-crop.
3. **Overlays the campaign message** (English by default; localizable) with an
   auto-contrast scrim so text stays legible on any hero.
4. **Stamps the brand logo** on each creative (optional).
5. **Runs compliance checks** — brand-color presence + a prohibited-word legal
   scan — and writes a machine-readable `report.json`.

The **web studio** additionally lets you assemble a campaign visually: pick or
upload a **person** and a **product** image (and an optional **logo**), fill in
region / audience / message, and watch Gemini compose a finished ad that
**combines those actual images as references** at 2K.

## 2. Quick start

```bash
# 1. Install (Python 3.11+)
pip install -r requirements.txt

# 2. Set your Gemini API key (free at https://aistudio.google.com/apikey)
export GEMINI_API_KEY=...            # Windows PowerShell: $env:GEMINI_API_KEY = "..."

# 3a. Run the CLI pipeline on a sample brief
python -m src.cli run briefs/skincare_launch.yaml --provider gemini

# 3b. …or launch the web studio
python -m src.web.server             # then open http://localhost:5000
```

All image generation uses Gemini, so a valid `GEMINI_API_KEY` is required.

### Windows launch (step by step)

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1           # if blocked: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
pip install -r requirements.txt
python -m src.web.server
```

Open `http://localhost:5000` (use an **incognito** window to avoid a cached
page). Every new terminal needs `.venv\Scripts\Activate.ps1` again.

## 3. Getting a Gemini API key

1. Go to **[aistudio.google.com/apikey](https://aistudio.google.com/apikey)**.
2. Sign in with a Google account and click **Create API key** (accept the
   default Google Cloud project if prompted).
3. Copy the key — it starts with `AIza…`.
4. In the web studio, open **⚙ Setup & keys**, paste it into **Gemini API key**,
   click **Save**, then **⚡ Test connection**.

> **Note on cost.** The Gemini image model is a premium model. There is a free
> tier, but image generation may require billing enabled on the Google Cloud
> project. If Test connection returns a billing/quota error, enable billing in
> Google Cloud (usage is per-image, not a subscription). Keep the key private.

## 4. The web studio, step by step

Launch with `python -m src.web.server` and open `http://localhost:5000`.

**⚙ Setup & keys** (top panel, opens on first launch)
- **Gemini API key** — required; powers all image generation.
- **Anthropic API key** — optional; only used by the legacy "describe a
  campaign" brief generator.
- **Output folder** — where finished creatives are written (blank = `./output`;
  point it at a Dropbox-synced folder to auto-upload).
- **Save** persists settings to a gitignored `.studio_config.json` so they
  survive restarts. **⚡ Test connection** fires one tiny Gemini call to confirm
  the key works before you run a full campaign.

**Create Campaign** (the builder)
1. **Campaign Brief** — brand/region and campaign message.
2. **Model** — the person reference: pick from the `assets/` folder, upload your
   own, or generate one with Nano Banana.
3. **Product** — the product reference, same three options.
4. **Logo** *(optional)* — upload a brand logo; it's passed to Gemini as a third
   reference image.
5. **Define Audience** — free-text audience.
6. **Paste a brief** *(optional)* — a JSON/YAML box that fills the fields above.
7. **▶ Run Campaign** — builds the brief and streams the pipeline live.
   **🗑 Clear cache** deletes cached heroes/outputs so the next run regenerates
   fresh images.

Each stage streams in live: the brief and legal check, then per product the hero
(labeled *generated*, *chosen*, or *reused*) and each of the three aspect ratios
as they're composited, with brand-color checks.

## 5. Architecture overview

```
                 ┌──────────────────────────────────────────────┐
                 │                Campaign brief                 │
                 │   (YAML/JSON, or assembled in the web UI)     │
                 └───────────────────────┬──────────────────────┘
                                         │  Pydantic validation (brief.py)
                                         ▼
   ┌───────────────────────────────  Pipeline (pipeline.py)  ───────────────────────────────┐
   │                                                                                         │
   │  for each product:                                                                      │
   │    1. Resolve hero ── reuse existing asset (storage.py)                                 │
   │                    └─ else generate ── GeminiProvider (providers.py)  ◀── references    │
   │    2. For each ratio {1x1, 9x16, 16x9}:                                                 │
   │         smart_crop → overlay_message → stamp_logo   (compositor.py)                     │
   │         brand_color_check  (checks.py)                                                  │
   │  3. legal_check on the campaign message  (checks.py)                                    │
   │  4. write creatives + report.json  (storage.py)                                         │
   │                                                                                         │
   └─────────────────────────────────────────────────────────────────────────────────────────┘
                                         ▲
                                         │  same pipeline, presented live over SSE
                 ┌───────────────────────┴──────────────────────┐
                 │        Web studio (web/server.py + UI)        │
                 └──────────────────────────────────────────────┘
```

The core principle: **the web UI is a thin presentation layer over the exact
same pipeline the CLI runs.** No business logic is duplicated in the browser.

## 6. Implementation walkthrough (module by module)

### `src/pipeline/brief.py` — the brief schema
Defines the data model with **Pydantic**, so every brief is validated before the
pipeline touches it:
- `Product` — `name`, `slug` (used as the output folder), optional `image_prompt`.
- `Brand` — optional `logo` path and a list of brand `colors` (hex).
- `CampaignBrief` — `campaign_name`, `target_region`, `target_audience`,
  `campaign_message`, optional `localized_messages` (locale → message), the list
  of `products`, and the `brand`. A validator enforces the task's
  **"at least two products"** rule. `slug` derives a filesystem-safe campaign id.
- `load_brief(path)` loads and validates from `.json` or `.yaml`.

### `src/pipeline/providers.py` — image generation
An `ImageProvider` abstract base hides the model behind one interface, so the
vendor is a one-class change. This build ships **`GeminiProvider`** (Google
"Nano Banana"):
- Uses the `google-genai` SDK. Reads `GEMINI_API_KEY` (or `GOOGLE_API_KEY`).
- `generate(prompt, refs=[...], aspect_ratio=...)` sends the text prompt plus any
  **reference images** (person/product/logo as base64) and renders at **2K**.
- `supports_references = True` — this is what makes person+product composition
  possible (text-to-image models cannot do this).
- Clear, actionable errors when the key is missing or rejected.

### `src/pipeline/storage.py` — assets & output
`LocalStorage` abstracts the filesystem: `find_asset(slug)` locates an existing
hero to reuse, `save_image(img, rel_path)` writes a creative. This is the seam
where an S3/Azure/Dropbox backend would drop in for production.

### `src/pipeline/compositor.py` — turning a hero into creatives
- `ASPECT_RATIOS` — the three required sizes (1080×1080, 1080×1920, 1920×1080).
- `smart_crop` — subject-aware center-crop + resize, so no image is distorted.
- `overlay_message` — fits and word-wraps the message, drawing a contrast scrim
  so text is always legible on any background.
- `stamp_logo` — composites the brand logo (top-left, scaled to frame width).
- `overlay_product` / `_remove_flat_background` — a Pillow-only helper that can
  knock out a flat product background and place the real product onto a scene
  (used by earlier composite experiments; kept as a utility).
- `build_creative(hero, ratio, message, logo)` — the one call that produces a
  finished creative for a given ratio.

### `src/pipeline/checks.py` — compliance
- `brand_color_check(image, brand_colors)` — samples a downscaled creative and
  reports whether the brand palette is present.
- `legal_check(message)` — scans the campaign message against a
  `PROHIBITED_WORDS` set (e.g. unverifiable superlatives) and returns any
  flagged terms. Results are structured data, written into `report.json`.

### `src/pipeline/pipeline.py` — the orchestrator
`Pipeline.run(brief, locale)` ties it together: resolve or generate each hero,
composite the three ratios, run brand checks per creative and a campaign-wide
legal check, then write every creative plus a `report.json` describing the run.

### `src/pipeline/brief_gen.py` — plain-language → brief (optional)
Turns a free-text description into a validated `CampaignBrief` using the
Anthropic API. Powers the optional "describe a campaign" path; needs
`ANTHROPIC_API_KEY`.

### `src/cli.py` — the command line
A **Typer** CLI. `python -m src.cli run <brief> --provider gemini [--locale es]
[--output DIR] [--assets DIR] [--verbose]` runs the whole pipeline and logs each
stage.

### `src/web/server.py` + `src/web/static/index.html` — the web studio
A **Flask** server that wraps the pipeline and streams each stage to the browser
over **Server-Sent Events (SSE)**. The single-page UI ("Campaign AI") is the
builder described in section 4. See section 8 for the API.

## 7. How image generation works (Nano Banana)

Gemini "Nano Banana" (`gemini-3.1-flash-image`) is **reference-conditioned**:
you pass it a text prompt *and* one or more input images, and it composes a new
image that incorporates them. That's what lets the studio take your **person**
and **product** (and optional **logo**) and generate a single finished ad, at
**2K**, rather than just a text-to-image guess.

In the builder, "Run Campaign" creates a two-product brief:
- **Ad (person + product)** — no pre-set hero, so it's *generated* by Gemini
  from a prompt built out of your audience/region/message, with the person,
  product, and logo images attached as references.
- **Product only** — uses your chosen product image directly, then composites
  the three ratios and message.

Both appear in the results stream, each with its three aspect ratios and checks.

**Multi-ratio rendering (no cut-offs).** A naive pipeline generates one image
and center-crops it to 9:16 / 16:9 — which slices off faces and logos. Instead,
for a generated ad this pipeline renders each ratio **natively**: it generates
the **1:1** master first, then for 9:16 and 16:9 it calls Nano Banana again,
passing the 1:1 as a reference with a *reframe* prompt ("keep the person,
product, and logo fully visible; extend the scene to fill the new format").
Because generation is reference-conditioned, the model recomposes and extends
the background rather than cropping — so subjects stay in frame at every ratio.
This costs three image generations per ad (1:1 + two reframes) instead of one;
that trade is intentional for output quality. If a reframe call fails, the
pipeline falls back to a crop so the run still completes.

> **Honest note on fidelity.** Reference-conditioned generation is not a
> pixel-perfect copy — the person, product, and logo are recognizably *based on*
> your images and styled into the scene, not cut-and-pasted. For a crisp,
> unaltered logo you would stamp it on afterward (the `stamp_logo` helper exists
> for exactly that on the composited creatives).

## 8. The web server & API endpoints

All under `src/web/server.py`. The browser never runs pipeline logic; it calls
these and renders the stream.

| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/` | GET | Serve the single-page studio. |
| `/api/config` | GET / POST | Read (masked) / save settings to `.studio_config.json`. |
| `/api/test_connection` | POST | One tiny Gemini call to verify the key. |
| `/api/assets` | GET | List folder images available to the pickers. |
| `/api/asset_image` | GET | Thumbnail (data URL) for a chosen asset. |
| `/api/upload_image` | POST | Upload a person/product/logo image to the workspace. |
| `/api/generate_asset` | POST | Generate one slot image via Gemini from a prompt. |
| `/api/clear_cache` | POST | Delete cached heroes + prior output so runs regenerate. |
| `/api/builder_brief` | POST | Assemble a validated brief from the builder inputs + references. |
| `/api/run` | GET (SSE) | Run the pipeline and stream each stage as events. |
| `/api/generate_brief` | POST | (Optional) plain-language → brief via Anthropic. |

The SSE stream emits events the UI listens for: `brief`, `legal`,
`product_start`, `hero_generating`, `hero_ready`, `creative`, `product_done`,
`done`, `error`.

## 9. The campaign brief format

YAML or JSON, validated by `brief.py`. Example (`briefs/skincare_launch.yaml`):

```yaml
campaign_name: Summer Glow Launch
target_region: Spain (ES)
target_audience: women aged 25-40 interested in clean skincare
campaign_message: Radiant skin, naturally. Discover your summer glow.

localized_messages:                 # optional (use --locale es)
  es: "Piel radiante, con naturalidad. Descubre tu brillo de verano."

brand:
  logo: assets/brand/logo.png
  colors: ["#0A7E8C", "#F4B41A"]

products:                            # at least two required
  - name: Aura Glow Serum
    slug: aura_glow
    image_prompt: >
      Luxury facial serum glass bottle with dropper on marble, soft morning light
  - name: Pure Hydrate Cream
    slug: pure_hydrate
    image_prompt: >
      Premium moisturizer jar with water droplets, aqua and white palette
```

`briefs/energy_drink.json` is a JSON example that intentionally includes a term
the legal check flags, to demonstrate compliance reporting.

## 10. Outputs & the run report

Creatives are written under the output folder, organized per campaign / product
/ ratio:

```
output/summer_glow_launch/
├── aura_glow/
│   ├── 1x1/creative.jpg
│   ├── 9x16/creative.jpg
│   └── 16x9/creative.jpg
├── pure_hydrate/
│   ├── 1x1/creative.jpg
│   ├── 9x16/creative.jpg
│   └── 16x9/creative.jpg
└── report.json
```

`report.json` records, per creative: the hero source (reused/generated), the
brand-color check result, and the file path — plus the campaign-wide legal
check. It's structured for a downstream approval/QA workflow, not just console
output.

## 11. Configuration & keys

Keys and settings are managed in the web studio's **Setup & keys** panel and
persisted to a **gitignored** `.studio_config.json`:
- `GEMINI_API_KEY` — required for all image generation.
- `ANTHROPIC_API_KEY` — optional; only for the plain-language brief box.
- output folder — where creatives are written.

On the CLI, set `GEMINI_API_KEY` as an environment variable. Uploaded/generated
builder images live under `assets/_workspace/` (also gitignored).

> **Security:** `.studio_config.json` stores keys in plaintext on your machine
> for convenience. It's gitignored so it never reaches a repo — don't ship a zip
> with your keys saved, and rotate any key you paste somewhere public.

## 12. Design decisions

- **One provider interface.** Swapping the image model is a single class; the
  pipeline is vendor-agnostic by construction.
- **UI is a thin layer over the pipeline.** The web studio streams the *same*
  pipeline the CLI runs — no duplicated logic, so behavior can't drift.
- **Reference-conditioned generation.** Person + product (+ logo) are fed as
  real image references so the ad actually reflects the user's inputs, which
  plain text-to-image cannot achieve.
- **Storage abstraction.** Filesystem now; `LocalStorage` is the seam where
  object storage or a Dropbox backend drops in.
- **Asset reuse before generation.** Existing assets are preferred over a paid
  API call — directly serving the cost/efficiency goal.
- **Cached, clearable reruns.** Generated heroes are cached so reruns are cheap;
  a **Clear cache** control forces fresh generation when inputs change.
- **Legibility by construction.** A contrast scrim + auto-fitting/wrapping text
  guarantees the message reads on any hero.
- **Compliance as data.** Brand + legal checks emit structured results into
  `report.json` for approval workflows.

## 13. Assumptions & limitations

- **Gemini key required.** This build generates exclusively through Gemini
  "Nano Banana"; there is no offline/mock fallback, so a valid `GEMINI_API_KEY`
  is needed to produce anything.
- **Reference fidelity.** Gemini composes the person/product/logo references
  into a new scene; likeness and product/logo detail are strong but not a
  pixel-exact copy of the uploads.
- **Ratio rendering.** Generated ads are rendered natively per ratio (1:1 master
  + 9:16/16:9 reframes) so subjects aren't cropped, at the cost of three image
  generations per ad. Reused/uploaded heroes still use a center-weighted crop,
  which is not saliency/face-aware; a production version would add subject
  detection there too.
- **Brand-color check** samples a downscaled image for palette presence; it's a
  presence heuristic, not a brand-guideline engine.
- **Legal check** is a keyword scan over a starter prohibited-word list — a
  starting point for a real policy/legal-review integration.

## 15. Troubleshooting

- **Test connection fails with an auth error** → the key was rejected; recheck
  it at [aistudio.google.com/apikey](https://aistudio.google.com/apikey).
- **A billing/quota error** → enable billing on the Google Cloud project, or
  wait out the rate limit.
- **Still seeing an old image after changing inputs** → click **🗑 Clear cache**,
  then Run again.
- **The UI looks stale after an update** → hard-reload (Ctrl+Shift+R) or open an
  **incognito** window; the browser is caching the page.
- **`python` isn't found / opens the Store (Windows)** → reinstall Python with
  "Add to PATH" checked.
- **PowerShell won't activate the venv** → run
  `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` once, then retry.
